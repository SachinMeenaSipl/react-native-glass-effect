# 0.3.0 — release plan

Status: **draft.** Features are candidates until they're marked **Decided**.
Fill in the `Decision` and `Notes` fields as you go. Nothing here is committed to.

## Goal

Make the library usable outside bare React Native apps:

- **Expo apps** can install and use it, including Expo dev builds.
- **Web apps** (React, Next.js and similar) can render real glass in the browser, including server-side rendering.

Anything else in this file is secondary to these two.

## Expo and web support (primary goal)

### Where we start

- Web already has a `nativeBridge.web.ts` and a CSS `backdrop-filter` fallback in `FallbackGlass`. It works as a plain fallback, but nothing has been tested in a real web build.
- Expo Go already renders a plain-view fallback instead of crashing. That is not glass.
- Native code is a bare React Native module (`react-native.config.js`, podspec, Gradle). It autolinks in RN 0.76+ bare apps and Expo dev builds, but not in Expo Go.

### Expo

- [ ] **Decide the Expo Go story first** (see open questions). Expo Go only loads native modules that ship inside Expo's own app, so a third-party module like this one cannot run there without being rewritten as an Expo Module and accepted by Expo. Likely answer: support Expo **dev builds** (`npx expo run:ios` / `run:android`, or EAS Build) and keep Expo Go on the fallback.
- [ ] Expo config plugin: set iOS deployment target and any Android settings automatically during `expo prebuild`.
- [ ] Test matrix: an Expo SDK app on a dev build, on iOS and Android, with the renderers from the table below.
- [ ] Docs: an Expo install guide, including what happens in Expo Go and how to make a dev build.

### Web

- [ ] Build a web entry (`lib/module` variant or `.web.js` files) and test it with **react-native-web**.
- [ ] **Next.js**: SSR-safe. Nothing reads `window`, `document` or `Platform` at import time. Components render on the server and hydrate on the client without mismatch. Mark client components with `"use client"` where needed.
- [ ] Glass on web: CSS `backdrop-filter` by default. Check the browser fallback when `backdrop-filter` is unsupported (Firefox older versions, some Android WebViews).
- [ ] Web-specific behavior: `refraction`, `chromaticAberration` and `motionLighting` have no web equivalent; document which props do nothing on web.
- [ ] Test in Chrome, Safari and Firefox; include one Next.js app and one plain React (Vite) app in the example setup.
- [ ] Docs: a web install guide for React and Next.js.

## Open questions

- Is 0.3.0 the right number, or is this the 1.0.0 release?
- **Expo Go:** should Expo Go show real glass, or is a dev build the supported Expo path? Real Expo Go support needs an Expo Module rewrite and is outside our control.
- **Web scope:** is CSS `backdrop-filter` (approximate, no refraction) acceptable as the web look, or do you want a WebGL/Canvas renderer for web too?
- **React Native Web:** should the web build require `react-native-web`, or should it also work in plain React DOM apps without it?
- Old package `react-native-liquid-glass` also has `1.0.0` on npm. Is it a separate project, or should new releases go only to `react-native-liquid-glass-native`?

## Release checklist

From `CONTRIBUTING.md`:

1. Update `CHANGELOG.md` and the version in `package.json`.
2. `npm install && npm run typecheck && npm test && npm run check:android && npm run check:ios`
3. For native changes, run the example app on each target listed above.
4. Update the user guide for API changes and the architecture docs for internals.
5. `npm run prepare`, then `npm pack --dry-run` and check the file list.
6. `npm publish`.
7. Tag the release (`v0.3.0`) and push the tag.

## Status (feature/0.3.0-expo-web)

Verified:
- Expo Android: the in-repo example builds and runs on the Pixel_8 emulator (dev bundle from Metro). The header reads "renderer: shader · native: yes", the native glass renders, and the button counter increments on tap.
- Expo web: dev server and production export both render and pass the browser test (button increments, backdrop-filter applied, no page errors).
- Vite web and Next.js web: production build and browser test pass (after fixing a `global is not defined` error in the Vite example).
- Library: typecheck, 31 tests, prepare, check:android pass.

Known / not done:
- Expo Android fix for Windows: the build needs a short CMake staging directory or Windows long paths (see examples/README.md). The generated android/ folder carries this local change.
- Fabric logs "Could not find generated setter" for LiquidGlassViewManager and GlassBackdropManager on the emulator. The glass still renders and props apply, but this should be investigated.
- Expo Go: plain-view fallback only (by design).
- check:ios not run locally (needs clang++; runs in CI on Ubuntu).
- Not tested: iOS device or simulator, and Expo Go.
