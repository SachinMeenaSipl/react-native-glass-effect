# Examples

| App | Platform | Run |
|---|---|---|
| [`liquid-glass-expo`](liquid-glass-expo) | Expo dev build (Android, iOS), Expo web | `npx expo start` · `npx expo run:android` · `npx expo start --web` |
| [`web-vite`](web-vite) | React web (Vite) | `npm run dev` · `npm run build` |
| [`next-app`](next-app) | Next.js (App Router, SSR) | `npm run dev` · `npm run build && npm start` |

Each app links the library from the repository root (`file:../..`). Run `npm run prepare` in the repo root after you change the library.

On Windows, Next.js (Turbopack) can't follow the folder link npm creates. For `next-app`, run `npm pack` in the repo root and install the `.tgz` file instead.

## Example APK (CI)

`.github/workflows/example-apk.yml` builds the Expo example as a release APK (JavaScript bundled in, so it runs without a dev server) and publishes it:

| When | Where the APK goes |
|---|---|
| A push to `main` that changes the library or the example | The rolling pre-release **example-latest**, replaced on every build |
| A version tag such as `v0.3.0` | A release named after the tag |
| Manually (Actions → Example APK → Run workflow) | **example-latest** |

Each build also emails a download link when these repository secrets are set (Settings → Secrets and variables → Actions):

| Secret | Example |
|---|---|
| `SMTP_SERVER` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` (TLS) or `587` (STARTTLS) |
| `SMTP_USERNAME` | the account that sends, e.g. `you@gmail.com` |
| `SMTP_PASSWORD` | for Gmail, an [app password](https://myaccount.google.com/apppasswords), not your normal password |
| `MAIL_TO` | one or more addresses, comma-separated |

Without the secrets the APK is still built and published; only the email is skipped.

The APK is built for `arm64-v8a`, which covers practically every Android phone since 2017. It's signed with the debug key from the Expo template, so it installs on any phone and each build installs over the previous one; it's not meant for the Play Store.

### Building with Codemagic instead

`codemagic.yaml` (repo root) does the same build on [Codemagic](https://codemagic.io), outside GitHub Actions: a push to `main` or a `v*` tag builds the release APK, and Codemagic emails a download link itself (no SMTP setup). The free plan includes 500 build minutes a month.

One-time setup:

1. Sign in at codemagic.io with GitHub and add this repository (choose the `codemagic.yaml` configuration).
2. Put your address under `publishing.email.recipients` in `codemagic.yaml`.
3. In the app's settings on Codemagic, open **Webhooks** and add the webhook to the repository, so pushes and tags start builds.

Email download links expire after 24 hours by default (Codemagic settings → Artifact download links).

## Windows: Android build fails with `ninja: ... No such file or directory`

Windows limits paths to 260 characters. CMake's object paths repeat the full project path, so a project under a long folder (for example OneDrive) can exceed the limit. Either:

1. Enable long paths (needs admin, then a reboot): set `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled` to `1`, or
2. Point the CMake build directory at a short path in `android/app/build.gradle`:

   ```groovy
   android {
     externalNativeBuild {
       cmake {
         buildStagingDirectory 'C:/lgx-cmake/app'
       }
     }
   }
   ```

The `android/` folder is generated by `npx expo prebuild`, so this change is local and is not committed.
